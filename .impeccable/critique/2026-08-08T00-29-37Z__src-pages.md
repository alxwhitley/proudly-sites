## Anti-Patterns Verdict

**Not AI slop.** The site has an articulated, mostly-enforced creative position ("The Grounded Workshop"): one accent spent on the ask, one shadow in the whole system, real client proof, honest disqualifiers, and the newly-written DESIGN.md rules are largely true on screen. Residual template flavor: the homepage's three glyph-chip service cards and the numbered 1/2/3 principle list on /about echo the list-making grammar DESIGN.md now explicitly bans on /services.

**Deterministic scan (`detect.mjs --json src/pages src/components src/layouts`):** exit code 2, 2 findings, both pre-existing and already accepted — `overused-font` and `single-font-everything`, both pointing at the Lato body font (`BaseLayout.astro:30`). This was already classified as an intentional exception in an earlier session (Lato/Playfair is the established system, documented in DESIGN.md) and is not new.

**Targeted regression greps (Assessment B):**
- `color: var(--terracotta)` sitewide → 7 hits, all annotated. None color actual link *text*. Two are form-UI state (`.req` required-asterisk, focus-ring border on `/contact` and Church Studio — fine). Three are a decorative `↗` arrow glyph (`.bridge-arrow`, `aria-hidden`) inside a card-style link on all three service-detail pages, whose visible heading/body text is not terracotta.
- `class="eyebrow"` / `gold-dot` sitewide → only the three deliberately-kept case-study narrative headings in `CaseStudy.astro` ("The Moment" / "What We Built" / "What Changed"). `gold-dot` returns zero hits anywhere — fully retired.

## Overall Impression

The system is real and the tonight's rule changes mostly landed: terracotta is now buttons-only everywhere text links appear, eyebrows are gone sitewide except the one documented exception, and the corrected CTA press-into-fixed-shadow hover is implemented exactly as specified. Two defects the critique surfaced were fixed on the spot (see below). What's left standing is one real pre-existing image-rendering bug that undercuts the portfolio — this site's actual conversion tool — plus a handful of consistency/scope gaps that a freshly-tightened rule set naturally exposes in older content it wasn't written against.

## What's Working

1. **Church Studio is the model page.** Split hero anchored to a real build, hairline page-index with a sticky screenshot rail, an honest "who this is NOT for" disqualifier, a real price, FAQ, inline ask. Its local `height:auto` override is also why its build screenshot is the one image on the site that renders at the correct ratio — proof the rest of the site's pattern is fixable the same way.
2. **The corrected CTA hover mechanic is implemented exactly right.** Verified in computed styles: rest state 6px/6px offset shadow, hover state `translate(3px,3px)` + 3px/3px shadow — the shadow's absolute screen position never moves while the face presses into it. Mobile variant (4px→1px) matches too.
3. **Voice discipline holds up.** No wallpaper claims, no hype, disqualifiers stated plainly — copy consistently converts skepticism into reassurance per PRODUCT.md's own principles.

## Priority Issues

**[P0] Real screenshot images render at the wrong aspect ratio sitewide (Church Studio excepted).** Root cause verified with a computed-style probe: these `<img>` elements carry HTML `width`/`height` attributes (for CLS prevention) *and* a CSS `aspect-ratio` intended to derive height from width — but no rule explicitly sets `height: auto`, so the browser's attribute-derived height (e.g. `480px`, `620px`) wins as an independently-resolved dimension, the `aspect-ratio` property becomes a no-op, and `object-fit: cover` crops to the wrong box. Confirmed on `/services/branding` (declared 3:2, rendered 1.09 and 0.97), `/work` cards (declared 4:3, rendered 1.07 desktop / cropped further at 390px), and case-study heroes (declared 2:1, rendered 1.65). This is the portfolio — PRODUCT.md's stated primary conversion tool — visibly showing squashed/cropped client-site screenshots. Fix is one line per rule: add `height: auto;` alongside the existing `aspect-ratio` declaration in `CaseStudy.astro` (`.case-hero-visual img`, `.built-shot img`), `work/index.astro` (`.work-visual img`), `services/index.astro` (`.claim-visual img`), and the three service-detail pages (`.proof-visual img`). Pre-existing bug — not introduced by tonight's placeholder-ratio work, which only touched the `.ph-panel` sibling rules, not these `<img>` rules.
**Suggested command:** `/impeccable layout` scoped to the image rules named above, or a direct one-line fix per file.

**[P1] "Pricing" and "Blog" nav items point at anchors that don't exist.** Header (desktop + mobile) and footer link to `/#pricing` and `/#blog`; `index.astro` has no matching ids. Every click silently reloads the homepage with no feedback — worst for the price-sensitive buyer this brand courts with "clear pricing, agreed upfront." Related and already known: both Web3Forms access keys are still the placeholder string, so the entire contact-form conversion path errors on submit until real keys land.
**Suggested command:** `/impeccable harden` (dead-link / broken-state pass) once the pricing number and blog launch decisions are made — this is a content/product decision (per PRODUCT.md, the pricing number itself is still `[UNDECIDED]`), not a pure design fix.

**[P1] Terracotta used outside the buttons-only rule on card-icon accents.** The `.bridge-arrow` ↗ glyph on all three service-detail pages' "Bigger Picture" link cards, and the homepage's `.service-icon` glyphs on an untokenized `#fff0e9` tint, are terracotta-colored non-button UI. Not literally "inline text link color" (Assessment B's narrower grep correctly found no text-link violations), but a strict reading of the freshly-tightened One Voice Rule ("reserved for buttons only") catches these too. Deliberately left untouched tonight — Phase 2 of this run scoped explicitly to inline text links, footer links, and the CTA button, not general icon-accent color; flagging here for a follow-up pass rather than fixing unreviewed.
**Suggested command:** `/impeccable colorize` or a direct sweep, once Alex confirms whether card-icon accents should move to Espresso Black or get a dedicated exception written into the Colors section.

**[P2] "PROCESS" kicker on the homepage still reads as an eyebrow without the dot.** `index.astro:142`, `.process-intro > p`, color `#d1b791` (an untokenized value — doesn't match Honey Gold `rgb(243,192,69)` or Muted Label). Tonight's eyebrow sweep was deliberately scoped to the literal dot-plus-small-caps pattern named in the task; this label lacks the gold dot, so it was correctly left alone by that literal scope, but it still functions as a section-opener kicker in spirit. Worth Alex's call on whether the retirement should widen to cover dot-less kickers too, and whether `#d1b791` should become a real token or be replaced.
**Suggested command:** `/impeccable typeset` or a direct follow-up, pending that decision.

**[P2] The Whole-Or-Center Rule (new tonight) isn't yet true of existing content.** The /about thesis band ("A referral is a moment of trust…") and Church Studio's two consecutive left-set text-only bands ("Faster Because the Guesswork Is Gone" → "Live in One to Two Weeks") predate the rule and read left-of-center rather than fully centered. This is an expected gap between a brand-new policy and previously-shipped, previously-approved layouts — not something to mass-edit autonomously, since "fixing" it is a real layout decision on pages Alex has already signed off on, not a mechanical correction.
**Suggested command:** `/impeccable layout` on `/about` and Church Studio specifically, once Alex confirms the rule should apply retroactively to those bands (see Assessment A's open question below on whether the rule should be scoped to claim/stat/CTA bands rather than narrative prose columns).

**[Fixed during this pass] Church Studio inquiry-form labels were illegible.** `.field label` had been changed to Espresso Black to match `/contact` exactly, but Church Studio's card sits on the Dark Card surface (not white like `/contact`'s), producing ~1.5:1 contrast. Verified with a computed-style probe and a cropped screenshot, then corrected: label color restored to `rgba(255,255,255,0.9)` (its pre-existing, legible value) while keeping the white/cream input-field treatment from tonight's Phase 5. Same underlying principle as the footer-link carve-out already written into DESIGN.md — text color must match its actual host surface, not a token copied from a differently-colored surface.

**[Fixed during this pass] `/services`' hairline index stopped ~200px short of its container.** `.svc-index` carried a `max-width: 980px` with no centering inside its ~1180px section content box, so the Full-Bleed Rule (also new tonight) was violated by the list's own width constraint, not by any individual divider. Verified by measuring rendered width against its container, then fixed by removing the cap — the list and its hairlines now fill the full content column.
